核心结论：功能限制完全建立在客户端信任之上。 本地唯一事实来源是 UserModel.proEndDate / pro / teamPro 等字段（服务端同步后缓存于本地），三个判定函数仅做 DateTime.Now 本地比较——无签名、无防篡改、无逐功能服务端鉴权。修改本地用户记录或补丁两个返回指令即可解除全部 UI 层限制； 数据写入类限制（清单数量、日历订阅数）由服务端 API 二次校验，不在客户端控制面内。

三个核心判定函数（CIL 反编译还原）

UserManager.IsFreeUser — 是否免费用户token 0x060065B7 · rva 0x1F3034
if (_user == null)            return true;   // 未登录按免费处理
if (_user.proEndDate == null)  return true;   // 从未付费
return proEndDate.Value.Date < DateTime.Now.AddYears(-20);  // 异常古老数据兜底
语义：区分「从未成为 Pro」与「曾是 Pro」。只要 proEndDate 有正常值（哪怕昨天刚到期）都不算免费用户。
UserManager.ProExpired — Pro 是否已过期token 0x060065BC · rva 0x1F31A8
if (_user?.proEndDate == null)     return false;  // 无 Pro 记录
if (proEndDate.Value >= DateTime.Now) return false;  // 未到期
return proEndDate.Value.Date > DateTime.Now.AddYears(-20);   // 到期 → 过期
这是 VIP 权益的总闸门：唯一的判断就是本地系统时间与本地存储的 proEndDate 比较。
UserManager.InGraceDate — 到期宽限期token 0x060065C4 · rva 0x1F33A8
if (_user?.gracePeriod != true)    return false;  // 服务端宽限开关
if (proEndDate == null)              return false;
if (proEndDate.Value <= Now)         return false;  // 须仍未到期（推断：宽限展示窗口）
if (_user?.noGraceDate == null)      return false;
return noGraceDate.Value <= Now;
配合 SubscriptionGraceDateMessage / subscriptiongracedatewindow.xaml，到期后给予宽限提示（noGraceDate 语义为推断）。

安全评估

客户端信任（Client-Side Trust）设计弱点。 权益判定 = 本地字段 + 本地时间。绕过方式：① 篡改本地缓存的用户记录（TickTickDao + sqlite3.dll）将 pro / proEndDate 改为未来时间； ② 补丁 ProExpired 与 IsFreeUser 的返回指令（各一处 ldc.i4）。二者均可解除全部 UI 层限制（皇冠、主题、看板、排序、过滤器）。

服务端校验边界：清单数量、日历订阅数等数据写入类限制由 /api/v2/* 服务端复核，本地绕过无效——客户端补丁只能解锁「表现层」功能，无法伪造服务端配额。该结构属于典型的「UI 层信任客户端、配额层信任服务端」设计；风险敞口集中在表现层。

证据与边界
REA Evidence：ev_d37545c6…（程序集分类 managed PE/IL-only）、ev_ce1ce5d7…（主程序集超 64MB 表示预算，成员级证据改用同原则本地 CIL 静态解码：不加载不执行目标）、ev_dea33030…（TickTickModels 无 VIP 成员）、ev_5a932785…（Handler 为 C++/CLI 桥）。
