## 定位

评估给定依赖的风险程度。

## 边界定义

评估的对象是依赖，不是漏洞；评估的是com.alibaba:fastjson，不是com.alibaba:fastjson@1.2.83，不是CVE-2026-16723。

评估的目标有两个：

1. 判定目标依赖的风险程度
2. 如果是风险依赖，给出风险版本的范围，原因

## 评估策略

评估维度：漏洞类型、AVD VPR、Snyk VPR、XDB PoC

高危害漏洞：可以执行系统命令、操作系统文件、读取数据库的漏洞。

风险程度：忽略、低、中、高

- 查看这个依赖历史所有的漏洞，如果Snyk平台未披露过高风险、严重风险漏洞，那么认为风险程度忽略。
- 这个依赖披露的每一个高危害漏洞，在AVD VPR、Snyk VPR中的评级，至少有一个低或者中，那么认为风险程度是低。
- 这个依赖披露的所有高危害漏洞，在AVD VPR、Snyk VPR中的评级，存在两个高或者一高一严重，那么认为风险程度是中。
- 这个依赖披露的所有高危害漏洞，在AVD VPR、Snyk VPR中的评级，都是严重，那么认为风险程度是高。

可信程度：低、中、高

- 暂时不统计

## 工作流程

1. 拿给定的依赖名称去Snyk平台查漏洞清单，并同时记录CVE编号、漏洞类型、等级、影响范围。
2. 如果Snyk平台未披露过高风险、严重风险的漏洞，那么终止，评级为忽略。
3. 拿CVE编号去AVD平台检索，通过标题确认漏洞实例。
4. 去AVD平台的漏洞详情页拿漏洞等级。
5. 根据评估策略输出依赖的风险程度，以及最高风险的版本范围，原因。
